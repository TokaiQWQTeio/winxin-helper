# 微信群 @ AI 助手设计方案

## 使用场景

专用个人微信账号加入一个测试群。群成员真正 @ 该账号并提问时，助手在原群回复一次。普通群消息只作为该群的上下文；私聊、其他群和仅包含 `@昵称` 字符的普通文本均不触发回复。

目标运行方式是让 Windows 微信客户端保持登录和运行，助手在后台监听与回复，不要求微信窗口一直置顶。能否在窗口最小化、系统锁屏或远程会话断开时稳定运行，要分别实测；不把这些状态默认视为可用。

## 消息流程

```text
已登录的 Windows 微信客户端
  → 经过实测的界面接入器（群名、发送者、消息正文、真正 @ 信号、新消息去重）
  → 群白名单 / 自身消息过滤 / 去重
  → 同群近期消息和摘要
  → OpenAI 兼容的 HTTPS 模型 API，或本机 Ollama 模型
  → 回复长度检查
  → 在原群发送，并核实结果
```

当前仓库已实现消息处理、按群隔离、去重、本机模型客户端、摘要、原文保留期，以及微信实时监听与 UIA 发送器。`text` 群的单次和持续模式都曾实测成功，但模拟发送点击会移动用户鼠标，后台进程因此已暂停，自动发送配置已关闭。多人群识别仍缺第三位成员验证。

已加入 `watch-preview` 只读命令：读取首个白名单群当前界面可见的消息列表，以启动时的消息作为基线，之后只打印新增文本项和候选 @。它不会调用模型、记录正式数据库或发送微信消息。消息列表断开连续重叠时丢弃该轮新增项，以避免旧消息误判成新消息。

多人群发送者识别的当前进展：普通屏幕截图在微信被遮挡时不适用，`PrintWindow` 对本机微信返回黑画面；Windows Graphics Capture 在独立进程中能捕获被遮挡的完整窗口。根据 UIA 消息行位置截取该行昵称区域，离线 OCR 已在测试消息上读出 `TokaiTeio`，并用同一行的正文 OCR 核对消息位置。仍需不同群成员的样本检验误配风险。后台输入框的草稿写入和清除已通过无发送测试。发送按钮的后台 Invoke 调用只留下草稿，未发出消息；短暂切到前台、核对群和草稿、点击发送后，固定测试消息已发出并得到回显确认。

本机 DeepSeek 安装和离线问答测试已通过。用户在 `text` 群真正 @ `hi～` 提问“你好”时，问答预览识别出发送者 TokaiTeio，并生成“你好！有什么可以帮你的吗？”。用户随后明确授权发送这一条，UIA 发送器确认它出现在原群且输入框清空。另一次经用户授权的 `run-once` 单次自动联调成功，收到新 @ 后自动生成并发送一次，数据库投递状态为 `sent`，进程自行退出。持续监听仍未实测。

2026-09-22 至 23 日的实测：账号已打开 `text` 测试群；Windows UI Automation 能读取群标题和消息列表。同样使用全角 `～` 时，真正 @ 的消息控件显示 `@hi～` 后跟 U+2005 分隔符，手打普通文本没有该分隔符。会话列表还独立显示 `[有人@我]` 以及最新消息的发送者和正文；最新 @ 的发送者直接从这条会话预览配对获得，其他可见消息可使用 OCR。消息控件的 RuntimeId 在多次快照间变化，不能直接当作持久消息标识；监听器通过连续列表重叠识别新增消息，在重启时跳过旧消息。配置已改为全角 `hi～`。wxauto4 41.1.7 在本机未识别到已登录微信窗口，因此采用直接 UIA 接入。本机 Ollama `deepseek-r1:8b` 安装和推理测试已通过。

## 接入原则

- 用户自行在本机微信客户端登录专用账号；不向项目提供微信密码、验证码或会话数据。
- 优先评估基于 Windows UI Automation 的接入。当前微信 4.1.13.65 的消息控件可部分读取，但 wxauto4 41.1.7 在本机未识别到主窗口；需要自行实现并验证适配层，或找到经此版本实测可用的库。
- wxauto 文档说明 Plus 后台模式在大多数操作中无需将微信置顶，但部分操作仍需前台；最小化虽可用却不推荐。因此“后台运行”以普通窗口被其他窗口遮挡作为首个验收场景，再单独验证最小化和锁屏。
- 群白名单从一个测试群开始。仅处理列表中连续可确认的新增项；读取失败、群名不确定、发送者不确定或 @ 双信号不匹配时，不发送。重启后以当前消息建立基线，可能漏掉停机期间的提问。
- 云端模型密钥只保存在环境变量；本机 Ollama 不需要密钥，且只允许本机回环 HTTP 地址。聊天原文与诊断文件只在本机保存且不提交到 Git；原文默认保留 7 天，摘要可手动清除。
- 不使用协议破解、注入、内存或数据库读取来补足界面无法提供的信息。

## 实测验收

1. 在测试群分别发送普通消息、真正 @、手打的 `@昵称` 文本，以及助手自己的消息；确认只有真正 @ 触发一次回复。
2. 用至少两位不同群成员确认群名、发送者和正文能准确配对；重复读取与微信重启后不会重复发送。
3. 确认回复只发到原测试群，并能核实发送结果；不确定时停止重试并记录状态。
4. 用模型接口故障和网络中断验证失败时不误发、不跨群引用内容。
5. 当前发送已暂停；先确认不干扰用户桌面的发送方式，再决定是否重新开启。

## 下一步所需信息

需要另一位群成员的测试消息，用来验证多人群发送者识别；用户目前暂时没有第三位测试成员。本机 DeepSeek 模型、真正 @ 的预览、手动授权的模型回复、单次自动联调和 `text` 群持续监听均已通过。扩大使用范围前仍需多人群和微信重启后的测试。
